# Dependencies are added incrementally, one phase at a time, as each phase
# introduces a real need for them. See ARCHITECTURE.md for the phase plan.
# Versions are pinned exactly to what was installed and tested against,
# rather than left open-ended, so a future dependency release can't
# silently change behaviour underneath this project.

# --- Phase 1: vehicle simulation + shared schema foundation ---
python-can==4.6.1      # virtual CAN bus for the simulated ECUs
pydantic==2.13.3        # TelemetryEvent schema validation
pytest==9.1.1           # test runner

# --- Phase 2: UDS diagnostics ---
udsoncan==1.26.1        # UDS request/response vocabulary, client, encoding (client-only; no server)
can-isotp==2.0.7        # ISO-TP (ISO 15765-2) segmentation over the same virtual CAN bus
                        # NOTE: the importable module is `isotp`, but the PyPI package
                        # name is `can-isotp` -- there is no PyPI package literally named `isotp`.

# --- Phase 3: Edge Gateway core (ingest/validate/normalize/publish) ---
paho-mqtt==2.1.0        # MQTT client for publishing to local Mosquitto (and AWS IoT Core from Phase 5)
                        # NOTE: v2.x requires passing CallbackAPIVersion.VERSION2 explicitly to
                        # Client() -- confirmed via smoke test; the old default (VERSION1) still
                        # works but is deprecated.
# The Mosquitto BROKER itself is not a pip package -- it's installed via apt
# (`apt-get install mosquitto`) for local test runs, or run via
# docker/docker-compose.yml (eclipse-mosquitto:2 image) for manual/demo use.

# --- Phase 4: buffering, reconnect/backoff, fault injection ---
# No new dependency -- the persistent buffer uses sqlite3 (Python's own
# standard library), and the reconnect/backoff logic is built directly on
# paho-mqtt (already listed above under Phase 3).

# --- Phase 5: AWS IoT Core integration ---
# No new Python dependency here either, and deliberately no AWS SDK
# (boto3) -- AWS IoT Core's device endpoint is plain MQTT over TLS, which
# paho-mqtt (Phase 3) already speaks; only paho-mqtt's own tls_set() is
# used. AWS resource provisioning (infra/) is handled by Terraform, a
# separate tool, not a Python dependency of this project.

# --- Phase 6: Diagnostic Anomaly Analyzer ---
anthropic==1.5.0        # OPTIONAL advisory explanation layer only (analyzer/llm_explainer.py).
                        # The analyzer works completely without this being configured: no
                        # ANTHROPIC_API_KEY -> explain_anomaly() returns None immediately and
                        # is never called with a missing key. Deterministic rule detection
                        # (analyzer/rules.py) has no dependency on this package at all -- it
                        # is imported nowhere outside llm_explainer.py. See docs/analyzer-spec.md.

# --- Phase 10: Engineering Dashboard ---
# No new dependency. The originally pencilled-in fastapi/uvicorn turned out
# not to be needed: dashboard/backend/ uses the standard library's
# http.server (ThreadingHTTPServer) with Server-Sent Events, paho-mqtt
# (above) for its read-only telemetry subscription, and sqlite3 for a
# read-only buffer-depth query; dashboard/frontend/ is plain HTML/CSS/JS
# with no build step and no CDN.
